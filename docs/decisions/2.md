# 0002. CORS allow-list instead of a *.vercel.app pattern

Date: 2026-10-21
Status: Accepted (implementation later narrowed)

## Context
`server.js` previously accepted any origin matching `.vercel.app`. Anyone can deploy a page on Vercel that calls the Edubits API with a logged-in student's browser.

## Original decision
At the time, the allow-list included `FRONTEND_URL`, `CORS_ORIGINS`, two production Vercel domains, and localhost outside production. Requests with no `Origin` header (curl, health checks) were allowed.

## Current implementation
`backend/server.js` allows the exact `FRONTEND_URL` and localhost port 5173 outside production. It does not read `CORS_ORIGINS` or allow Vercel preview domains automatically. To use a preview, set `FRONTEND_URL` to that exact origin.

## Alternatives considered
Keeping the wildcard regex for preview deployments was rejected because previews can be deployed by anyone with access to the project. The implementation now uses a single explicit frontend origin.

## Consequences
Preview deployments need their exact origin configured as `FRONTEND_URL`. `trust proxy` is enabled (`app.set("trust proxy", 1)`) so the rate limiter can identify client IPs behind the hosting proxy.
